Course CoVAPSy, voiture TT-02 au 1/10

Teste ta voiture autonome avant de la poser sur la piste.

Le simulateur reproduit la voiture, son lidar, son ultrason et le règlement de la course. Tu écris ton algorithme en Python, tu le regardes rouler ici, puis tu copies le même code dans Webots ou sur la vraie voiture.

Ce qui est simulé

  • Le châssis TT-02

    Empattement de 25,7 cm, braquage de ±18° avec un servo qui met du temps à tourner, accélération et freinage limités. Trop vite dans un virage, la voiture glisse.

  • Le lidar RpLidar A2

    360 mesures par tour, avec un peu de bruit. Comme sur la voiture, seul l'avant est utile : de -90° à +90°.

  • L'ultrason arrière

    Un cône de ±12°, de 2 cm à 2 m, pour reculer sans taper quand la voiture est coincée.

  • Le règlement

    Une voiture immobile plus d'une seconde, c'est un arrêt. Rouler à contresens est compté aussi.

La voiture violette

C'est l'exemple le plus abouti. Elle fait d'abord un tour de reconnaissance prudent en dessinant une carte de la piste avec son lidar. Elle calcule ensuite la trajectoire la plus rapide, puis elle attaque en se repérant sur sa carte.

Quand une voiture plus lente la gêne, elle cherche un passage à côté pour la doubler. Son code complet est dans Code des voitures, en JavaScript et en Python pour Webots.

Lecture seule

Écrire son code

Dans le menu « Algorithme », choisis + Créer un algorithme… et donne-lui le nom que tu veux. Il apparaît ensuite dans « Mes algorithmes » pour toutes les voitures : plusieurs voitures peuvent utiliser le même. Tu peux l'écrire en Python (le même langage que sur la vraie voiture et dans Webots) ou en JavaScript. Le code est appelé toutes les 32 ms, comme une boucle while driver.step() != -1 dans Webots : c'est le contenu de la boucle, pas besoin de l'écrire.

En Python

  • Les variables normales repartent de zéro à chaque appel. Pour garder une valeur, utilise le dictionnaire memoire : memoire["compteur"] = memoire.get("compteur", 0) + 1.
  • return arrête le code pour ce pas-ci. Tu peux définir des fonctions avec def, et math et random sont déjà importés.
  • print(...) s'affiche dans le journal, sous la piste.
  • La première fois, Python met quelques secondes à se charger (il faut internet), ensuite le navigateur le garde.

Ce que tu peux lire

  • tableau_lidar_mm[i] : distance en mm à i degrés. 0 devant, 90 à gauche, -90 (ou 270) à droite. Le lidar ne voit que vers l'avant, de -90 à +90 : derrière, et quand rien n'est vu, la valeur est 0.
  • vitesse_actuelle : vitesse mesurée en m/s.
  • temps : temps simulé en secondes.
  • memoire : gardé d'un appel à l'autre, par exemple memoire["compteur"] en Python (memoire.compteur en JavaScript).
  • ultrason_arriere_mm : distance mesurée par l'ultrason arrière (cône de ±12°, jusqu'à 2 m). Vaut 0 si rien.
  • sens_inverse : vrai (True en Python) si la voiture est à contresens (bordure rouge à droite). Sur la vraie voiture, il faut le détecter, par exemple avec une caméra.

Ce que tu peux commander

  • set_vitesse_m_s(v) : vitesse visée en m/s, négative pour reculer, 7,8 m/s max (28 km/h).
  • set_direction_degre(a) : braquage en degrés, positif vers la gauche, ±16° max.

Règlement

La voiture doit toujours rouler : immobile plus d'1 s, c'est un arrêt. Elle ne doit jamais rouler à contresens. Le chronométrage compte les deux.

Passer à Webots

L'onglet « Python (Webots) » donne un contrôleur prêt à copier dans controllers/<nom>/<nom>.py, avec les mêmes noms de fonctions. Pour un algorithme écrit en Python, l'onglet « Fichier Webots complet » donne directement le contrôleur entier, avec ton code dedans. Pour un algorithme en JavaScript, la boucle est fournie et ton code y est recopié en commentaire, à traduire.
